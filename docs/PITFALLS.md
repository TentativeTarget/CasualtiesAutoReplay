# 踩坑记录

按"现象 → 原因 → 结论"整理。**改代码前先扫一遍，很多坑会重复踩。**

---

## 一、录制与实体同步

### 1. 主机自己的攻击/特效不产生网络消息

**现象**：回放里主机挥爪没有动作；主机开枪没有枪口焰。

**原因**：
- 攻击转播走 `ServerMain.GetListOfClientIdsExceptThisAndHost(id)`，
  两人局（主机 + 1 客）时这个列表是**空的**，消息根本发不出去。
- 主机自己的动作在本机直接执行，不经过网络。

**结论**：
- 给这类列表注入一个**假客户端 id**（`InjectFakeClient` / `FakeClientId=250`），
  让"只发给其他客户端"的消息也发一份（发给假 id，不会真的发出去），发送钩子就能录到。
- 但**主机自身**的挥爪/开枪仍不产生消息 → 必须用**本地事件补录**：
  `ReplayKind.Swing`（挥爪）、`ReplayKind.Fx`（粒子/音效/弹道/姿势）。

### 2. `ArmsSwing` 是每帧刷的，不能当攻速

**现象**：录出来的挥爪记录一秒二十多条（间隔 24ms）。

**原因**：游戏在攻击期间每帧调用 `armsAnimator.Play("ArmsSwing")`；
而且**枪械射击也会走 `Body.Attack`**（同样的 `ArmsSwing`）。

**结论**：
- 不要用动画回调当"一次攻击"。用**真实事件**：近战用 `Body.Attack` 的返回值，
  枪械用**枪口焰粒子**（一发一次）。
- 去重只能合并"同一帧的重复"（<20ms），不能按固定节奏截断，否则会改掉武器攻速。

### 3. 枪械的持枪姿势是动画参数，不是独立动画层

**现象**：回放里拿枪还在"挥爪"；切割机姿势不对。

**原因**：
- 手臂只有 **1 层** Animator，`gun`（bool）和 `gunangle`（float）驱动
  `ArmsGunUp / ArmsGunStraight / ArmsGunDown` 之间混合。
- 但 `Body.Attack` 里是**直接** `armsAnimator.Play("ArmsSwing", -1, 0)`，**绕过状态机**，
  所以设 `gun=true` 也拦不住。
- 切割机**不是 `GunScript`**，按组件判断会漏。

**结论**：
- 回放时拦截 `Animator.Play`：持枪类武器禁止播 `ArmsSwing`。
- 判断"是不是持枪类"不要看组件类型，**直接录游戏自己设的 `gun` / `gunangle` 参数**
  （`ReplayKind.Fx` 类型 3），回放时原样设回去。

### 4. 中途请求全量基线 = 十几秒实体冻结

**现象**：回放到某个关键帧之后，**实体完全不动但动画正常**，持续十几秒。

**原因**：录制端在每个关键帧调用 `RequestFullBaseline`，
回放时这批基线会把**所有实体销毁重建**。

**结论**：我们的跳转模型是"**重载场景 + 从头重放**"，中途基线毫无用处，删掉。
（如果以后要做"不重载直接跳"，才需要重新引入，并且要改成"覆盖状态"而不是"重建实体"。）

### 5. 关键帧全量地形快照 = 卡顿

**现象**：关键帧处轻微卡顿，实体像被定住。

**原因**：关键帧 `BeginDump(forceFull: true)` 会清空"已发次数"计数，
导致八百多个地形块**全部重发**。

**结论**：
- 关键帧不再做全量地形快照。
- 地形快照节奏：**开录首帧全量**、**换层全量**、**每 60 秒增量（哈希比对）**、
  **每 180 秒全量兜底**（仍然分帧发送，`MaxChunksPerCall=192`）。

### 6. 地形块记录会堵住实体更新

**现象**：换层瞬间实体卡住。

**原因**：播放循环遇到 Chunk 记录超预算就 `return`，后面的实体记录全被压在它后面。

**结论**：Chunk 超预算时进队列（不要 return），并给地形写入**每帧 4ms 的时间片上限**，
保证帧率不掉。

### 7. `WorldGate` 死锁

**现象**：跳转后卡 40 多秒（正好是 45s 超时）。

**原因**：播放循环先等"世界存在"再投递，但**世界正是靠投递的记录建出来的**。

**结论**：
- `_seeking` 期间**不要**过 WorldGate。
- WorldGate 只在**整段回放的第一次引导消息**后等待一次；换层时会有新的种子公告，
  那里**不能**再停（否则换层就 freeze）。

## 二、回放管线

### 8. LiteEntitySystem 只能初始化一次

`LiteEntitySystemInit()` 二次调用直接抛 `"EntityManager already exists!"`。
所有初始化都走 `Net.OnTransportConnected()`，所以**不能**在回放里再手工建一次。

### 9. 跳转 = 重载场景

`Seek()` 的实现是 `SceneManager.LoadScene("SampleScene")` + 从头重放 + 静默快进。
场景名在**内容建好之前**就已经是 `SampleScene`，所以判断"就绪"还要看
`WorldGeneration.world.worldExists`（最多等 8 秒）。

### 10. 残留的假玩家会刷屏 NRE

**现象**：日志被 `ClientMain.OnGUI -> NullReferenceException` 刷爆（上万条）。

**原因**：每次跳转都新建 `ScavPlayer` 空壳，旧的没销毁。

**结论**：`ReplayBridge.DestroyAllPlayers()` 在重开前清场；
回放里的"壳玩家"要禁用 `Body`（否则会饿死/辐射），并定期清零 `radiationSickness`。

### 11. 血迹/滴落粒子被剔除

Mod 的 `BodyViewParticles` 按"本地玩家所在区块"剔除粒子，回放里壳玩家在远处 → 粒子全没了。
回放期间跳过这个 Tick。

## 三、UI（IMGUI）

### 12. IMGUI 不拦截游戏输入

我们的面板点到按钮时，游戏也收到了点击。
→ 面板打开期间给 `Input.GetMouseButton*` / `GetAxis*` 打补丁返回空值
（我们自己的 UI 用 `Event.current`，不受影响）。

### 13. 九宫格贴图会带出杂线

**现象**：用游戏 UI 贴图做九宫格边框时，画面里出现贯穿屏幕的细线。

**原因**：`ReplayNineSlice` 采样贴图外围 3px，这张贴图的装饰线被一起拉伸。

**结论**：边框改成**纯色实线**（`SolidFrame`），四边等宽，干净。

### 14. 字体

- 游戏 IMGUI 字体是 `CoopAssets.gamefont`（RetroGaming 系列），**没有中文字形**，
  中文靠另一个插件（Together Chinese Name Fix）注入的回退字体。
- 想统一：直接反射取 `Together.CoopModAssets.gamefont`（`RetroGaming_200`），
  细体用同 bundle 里的 `RetroGaming_100`。
- **不要覆盖** `GUI.skin.font`，否则中文回退会被顶掉。

### 15. Unity 运行时无法从 TTF 建 Font

`Font` 只能从 AssetBundle 或系统已安装字体创建。
自己打包的 bundle 会因为**内容哈希相同**被 Unity 判为"已加载"而拒绝（即使改了内部名字）。

## 四、格式与工具

### 16. v6 / v7 关键帧长度不同

- v6：32 字节（无层号）
- v7：36 字节（末尾多一个 `i32 biome`）

读的时候必须按 `LayoutVersion` 分支，否则整张表错位。

### 17. 回放时"重播原版行为"比"自己画特效"保真

**做法**：回放特效直接调用游戏自己的方法（例如守卫近战 `MeleeAttack` 协程），
不要自己复刻动画/粒子。

**为什么安全**：即使这个方法会改血量、触发音效，
后面紧跟着的同步包会把实体状态纠正回录制时的值，
所以"多打了一下"玩家看不到。

**边界**：涉及**场景结构**的（生成/销毁物体、改地形）不能乱调，
只调"表现 + 数值"类的方法。

### 18. 物种不是身体对象名

`Body.gameObject.name` 是 `Body_玩家名`。
真正的物种是 `Body.charType`（0=Experiment / 1=Milky / 2=Dune）。

### 19. 层名用游戏的层名表

`WorldGeneration.biomeTitles[biomeDepth]`（运行时读），比自己写死对照表可靠。

### 20. 大文件读写要小心（开发过程坑）

本仓库的 `ReplayRecorder.cs` / `ReplayPump.cs` 已经超过 50KB。
编辑器/工具的"读全文 → 改 → 写回"流程如果读取有上限，会**静默截断文件**。
→ 改大文件只用**定点替换**，改完检查行数与结尾括号。

## 五、死亡

### 21. 怪物死亡不是 `Body` 死亡

**现象**：回放里怪被杀掉后没有死亡动画。

**排除过程**：
- 怪不是 `Body`；
- 不走 `GuardScript.Die`；
- 也没被 `Destroy`（死亡瞬间只有音效对象和 `HitFlash` 被销毁）。

**原因**：死亡入口因怪而异（蜘蛛是 `SpiderHandler.AnimalDeath`），属于**客户端本地表现**，
网络流里没有可直接重放的等价消息（同 PITFALLS #1 的思路）。
怪种很多，写死某一个方法必然漏，所以改成**泛化补录**。

**结论**：
- 启动时扫 `Assembly-CSharp` / `CasualtiesMP`，把所有名字像死亡的实例方法
  （`Die` / `Death` / `Kill` / `*Death` / `*Die`，返回 void、0~1 个参数、挂在 MonoBehaviour 上）
  统一挂 `ReplayDeathHook` 的后置补丁；玩家身体（`Body` / `NetBody` / `ScavPlayer`）排除；
- 触发时记 `ReplayKind.Fx` 子类型 5：位置 + `类型名|方法名` + 参数个数（玩家 60m 内）；
  同一对象 0.5 秒内只记一次，躲开"基类+子类"和 `AnimalDeath → Die` 这种调用链；
- 回放端没有稳定的实体 id 映射，按**类型名**找 **4m 内最近的对象**，反射调同一个方法
  （有参数就用 `default` 填）；
- 所以同类型怪挨太近时可能重放到错的那只 —— 想更准要把怪物实体 id 一起录进去；
- 旧录像里的子类型 4（蜘蛛专用）保留读取，不会失效。

## 六、覆盖层与输入

### 22. 覆盖层（F9）会吃掉游戏 UI 的点击

**现象**：回放里能看到游戏自己的控制台/HUD，但点不动、也打不了字。

**原因**：我们的 IMGUI 面板永远绘制在游戏 uGUI 之上，落在面板区域内的鼠标事件被 IMGUI 消费；
按 F9 把覆盖层关掉就恢复正常。

**结论**：
- 这**不是** `GuiBlock`（跳过 `UIInGame._GUI_DoInGameUI`）的问题 —— 那条补丁必须保留，
  关掉它会让回放里的视角出错；
- 临时办法就是关覆盖层；以后要做的是"游戏控制台打开时自动收起覆盖层"。
- 同理：回放期间**不再锁光标**、`BlockMoveInput` 默认关闭，这两条都验证过没有副作用，
  不要为了"防误操作"再把光标锁回去。
